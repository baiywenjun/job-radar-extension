# 岗位雷达 · JD 结构化记录仪

在你**已登录**的招聘网站岗位详情页，把 JD 结构化留存并按信号词打分，用来区分「真在建设的岗位」和「外包换名 / 培训招生 / 长期挂着的僵尸岗」。

规则库直接来自《热门紧缺岗位投递关键词速查表》：五类岗位族群（AI 应用 / FDE 交付 / AI Infra / 智驾具身 / 政企）+ 强信号、弱信号、反向排除词。

---

## 它不做什么

这一条比功能列表更重要：

- **不批量翻页、不抓搜索结果、不并发请求**——只在你看的那一页、你点的那一下工作
- **不绕过登录、验证码、访问控制**
- **不采集招聘者姓名、联系方式等个人信息**（入库字段里刻意没有简历/HR 信息）
- **不上传任何数据**，全部留在本机 IndexedDB
- **不做对外提供或商业化**——一旦对外分发数据，性质就从「个人辅助阅读」变成「招聘信息服务」，会撞上平台不正当竞争红线

依据：北京互联网法院 2026-06 生效判决（首例适用《反不正当竞争法》第十三条第三款「数据专款」）认定的不正当竞争，行为要件是**绕过登录验证/访问权限 + 批量抓取 + 对外提供 + 经营者身份**。本工具刻意避开这四项。平台《服务协议》仍普遍禁止自动化采集，账号风险请自行评估。

## 安装

1. 打开 `chrome://extensions`（Edge 为 `edge://extensions`）
2. 打开右上角「开发者模式」
3. 点「加载已解压的扩展程序」，选择本目录 `job-radar`
4. 在工具栏把「岗位雷达」固定出来

无需构建、无依赖、无需服务端。

---

## 使用

1. 打开 **BOSS 直聘 / 猎聘 / 脉脉 / 国聘** 的岗位详情页
2. 右侧出现面板：评分、档位、字段、命中词一目了然
3. 点「保存到本地库」，或在面板上「复制摘要」
4. 点工具栏图标打开本地岗位库：筛选、统计、导出 CSV / Markdown

面板字段右侧的小标签会告诉你每个字段是怎么来的：`选择器` / `标题推断` / `页面` / `未取到`。**标「未取到」就是要校准的信号。**

## 面板没出现怎么排查

按顺序做，三步就能定位到具体环节。**改过代码后必须做第 1 步**，否则浏览器跑的还是旧版本。

**1. 重新加载扩展**

`chrome://extensions` → 找到「岗位雷达」→ 点卡片上的刷新按钮（↻）→ 回到页面按 `F5` 强制刷新。

只刷新网页不重新加载扩展，改动不会生效。

**2. 打开 Console 看有没有这一行**

按 `F12` → 切到 **Console** → 筛选框输入 `岗位雷达`。三种结果对应三种原因：

| Console 结果 | 含义 | 处理 |
|---|---|---|
| `[岗位雷达] 已注入 · BOSS 直聘 · https://...` | 脚本正常跑起来了 | 看第 3 步 |
| `[岗位雷达] 当前域名不在支持列表：xxx` | 该域名不在覆盖范围 | 需在 `manifest.json` 的 `matches` 与 `src/content/adapters.js` 里加该站点 |
| **完全没有输出** | 内容脚本没被注入 | 扩展加载失败，或站点 URL 不匹配 `matches`。到 `chrome://extensions` 看该扩展有没有红色错误 |

**3. 按注入后的表现判断**

| 现象 | 原因 | 处理 |
|---|---|---|
| 右侧出现「未能识别本页岗位」的诊断卡 | 站点识别对了，但字段全部抽不到 —— 通常是**该站改版后类名变了** | 诊断卡里列出了站点与 URL，按下一节校准选择器 |
| Console 有 `[岗位雷达] 已渲染 · ... · JD N 字` 但看不到面板 | 面板被站点样式遮挡或位置超出视口 | 缩小页面（`Cmd -`）看是否露出；或反馈该类站点做定位适配 |
| Console 什么都没有，`chrome://extensions` 也无报错 | 页面 URL 不匹配 | 确认是 `https://www.zhipin.com/job_detail/xxx.html` 这类**详情页**，而不是搜索列表页 |

补充两点行为说明：

- **从搜索列表点进详情**（BOSS、脉脉是单页应用，URL 变了但页面不重新加载）已做了处理：脚本会在检测到 URL 或页面标题变化后自动重新抽取，不需要手动刷新。
- **详情面板延迟渲染**时会自动重试最多 8 次（每次间隔 700ms），抽不到才会显示诊断卡，不会一上来就判定失败。

## 分数怎么算

基线 26 分，加减项如下。所有加减分都会在面板上列出理由，分数永远可以人工复核。

| 维度 | 权重 | 举例 |
|---|---|---|
| 技术栈词 | 每项 +6，最多 10 项 | vLLM、SGLang、PD 分离、TTFT、LangGraph、MCP、VLA、世界模型 |
| 建设动作 | 每项 +6，最多 2 项 | 迁移、替换、二次开发、源码级、从 0 到 1、调优、压测、上线 |
| 工程指标 | 每项 +5，最多 3 项 | QPS、P99、回归评测、监控告警、故障兜底、SLA |
| 族群归属 | 命中 +4 / 未归类 −8 | 判定到五类之一 |
| 弱信号 | −8 ~ −30 | 熟悉 ChatGPT、纯提示词、劳务派遣、人天计价、零基础包就业 |
| 排除词（**只扫标题**） | −25 | 初级前端、手工测试、NLP 算法、Prompt 工程师 |
| 薪资倒挂 | −12 | 5 年以上经验却 ≤15K |

排除词只看标题和 JD 前 120 字，**不扫正文**，避免误伤正文里正常的职责描述。

分数曲线经过标定：技术词 4 个≈中性，6 个≈中上，8 个以上才够强信号——「沾两个技术名词」拿不到高分。

### 五个档位

| 档位 | 含义 | 建议 |
|---|---|---|
| 强信号（≥80） | 有具体技术栈与建设项目 | 优先投 |
| 中性（55–79） | 方向对得上，证据不足以判断真假 | 投前核 JD 细节 |
| 偏弱（35–54） | 信号偏弱或有减分项 | 谨慎 |
| 高概率伪岗（<35） | 命中多项减分项 | 直接跳过 |
| 信息不足 | JD 抽得太短（<120 字） | 不下结论，先点「重新抽取」 |
| 非目标岗位 | 一个目标族群词都没命中 | 只对五类岗位打分 |

「已挂牌 N 天」**不扣分**。长期挂牌可能是高流动岗位持续招聘，也可能是僵尸岗，只做提示。首次记录时间由本地库维护，同一天多次看到同一岗位只累加次数。

## 抽不到字段怎么校准

招聘平台改版频繁，选择器一定会失效。校准路径很短：

1. 在详情页按 F12，用元素选择器点中目标字段，看真实的 class
2. 打开 `src/content/adapters.js`，找到对应站点（`zhipin` / `liepin` / `maimai` / `iguopin`），把新选择器**加到数组最前面**
3. `chrome://extensions` 里点本扩展的刷新按钮，再刷新页面

### 抽取是怎么走的

选择器只是一层，真正决定准确率的是后面的结构兜底。顺序如下：

| 步骤 | 逻辑 | 面板上的来源标签 |
|---|---|---|
| 1 | 先定位 JD：依次试 `jd` 选择器 | `选择器` |
| 2 | JD 抽不到时，找「岗位职责/任职要求」关键词所在**最近的**语义容器 | `启发式` |
| 3 | 以 JD 元素为锚点向上爬，找到同时含薪资与经验的**最小祖先**，作为「详情区」 | — |
| 4 | 职位名/公司/薪资先在该详情区内试选择器 | `选择器·区` |
| 5 | 区内仍抽不到，用结构推断：标题元素、工商后缀、金额模式、经验模式 | `结构推断` |
| 6 | 最后才从页面标题 `<title>` 解析 | `标题推断` |

两个关键点：

- **`选择器·区` 与 `选择器` 的区别**：前者限定在详情区内，后者是全文档。BOSS 搜索页是「左侧列表 + 右侧滑出详情」，两边类名会重复，全文档抽会抓到列表卡片——这也是最初把职位名抽成列表项的原因。
- **列表项识别作为最后防线**：如果某站薪资区块与 JD 区块并列、公共祖先就是整页，详情区收窄会失败。此时靠「同 class 兄弟 ≥3 即视为列表卡片」跳过左侧列表。实测中这条能兜住收窄失败的情况。

如果 JD 正文整个抽不到，面板会显示「JD 来源：未取到」并提示信息不足——这时优先补 `jd` 数组。

## 已知局限

1. **只覆盖 4 个平台的网页版**。企业官网、国聘之外的政企渠道结构各异，需要按同样方式加 adapter。
2. **采集不到猎头与内推市场**。AI Infra、智驾核心、具身智能全栈这类岗位本来就不公开挂牌（供需比低至 0.15），工具再强也看不到。
3. **样本有偏**。库里只有你实际浏览并保存的岗位，不能当全市场缺口用；它适合做「一手样本库」去校验聚合报告，不适合直接推结论。
4. **不是投递工具**。不自动投递、不自动打招呼。

## 目录结构

```
job-radar/
├── manifest.json
├── icons/
├── preview.html           # 自包含预览页（npm run build:preview 生成）
├── src/
│   ├── common/
│   │   ├── util.js        # 文本归一化、词条匹配、薪资/经验解析
│   │   ├── rules.js       # 五类族群词库 + 打分引擎（核心）
│   │   └── db.js          # IndexedDB 封装
│   ├── content/
│   │   ├── adapters.js    # 四个站点的选择器与详情页判定
│   │   ├── extract.js     # 抽取：选择器 → 标题解析 → 文本启发
│   │   ├── panel.js       # 侧栏面板（Shadow DOM 隔离）
│   │   └── main.js        # 编排、保存、复制
│   ├── background/sw.js   # 消息代理 + 落库（内容脚本不直接写库）
│   └── popup/             # 本地岗位库：统计、筛选、导出
├── tests/
│   ├── run-tests.js       # 规则引擎用例（10 条断言）
│   ├── dom-test.js        # jsdom 抽取 / 降级 / 列表防线 / 面板交互（58 条断言）
│   ├── preview-smoke.js   # 预览页冒烟测试（10 条断言）
│   ├── build-preview.js   # 生成自包含 preview.html
│   └── demo.html          # 预览页源文件
└── README.md
```

**架构上有一个必须说清的点**：内容脚本里的 `indexedDB` 访问的是**招聘网站 origin** 的库，不是扩展的。所以内容脚本一律通过 `chrome.runtime.sendMessage` 把数据交给 service worker 落库，避免把数据写进别人家的站点存储。


## 修改词库

改 `src/common/rules.js` 顶部的 `GROUPS` / `WEAK_TERMS` / `EXCLUDE_TERMS` 三个数组即可，改完刷新扩展。词条是纯数据，不需要动打分逻辑。

新增族群时注意：`title` 只用于判定岗位归属，`tech` 才计入强信号；同一个词出现在多个族群里只会被计一次分。
