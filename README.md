# 岗位雷达 · JD 结构化记录仪

在你**已登录**的招聘网站岗位详情页，把 JD 抽出来、交给你自己写的判定标准判一遍，用来区分「真在建设的岗位」和「外包换名 / 培训招生 / 长期挂着的僵尸岗」。

判定有两条通路并存：**本地词库**（毫秒级，离线可用）和**你自己的模型 API**（读 JD 原文 + 你的标准，给出档位与证据）。面板先出本地结果，模型结论到达后原地替换，底部永远写明当前看到的是谁的结论。

## 它不做什么

这一条比功能列表更重要：

- **不批量翻页、不抓搜索结果、不并发请求**——只在你看的那一页、你点的那一下工作
- **不绕过登录、验证码、访问控制**
- **不采集招聘者姓名、联系方式等个人信息**（入库字段里刻意没有简历/HR 信息）
- **不主动外发数据**：只有你自己配的模型 API 会收到内容，且仅限当前岗位的字段与 JD（首次判定前有一张写清"发什么、发给谁、不脱敏"的确认卡）；其余全部留在本机 IndexedDB
- **不做对外提供或商业化**——一旦对外分发数据，性质就从「个人辅助阅读」变成「招聘信息服务」，会撞上平台不正当竞争红线

依据：北京互联网法院 2026-06 生效判决（首例适用《反不正当竞争法》第十三条第三款「数据专款」）认定的不正当竞争，行为要件是**绕过登录验证/访问权限 + 批量抓取 + 对外提供 + 经营者身份**。本工具刻意避开这四项。平台《服务协议》仍普遍禁止自动化采集，账号风险请自行评估。

## 配模型 API 与判定标准

### 1. 填 API Key

点工具栏图标打开弹窗 → 右上角齿轮 → 填 `baseURL` 与 `API Key`：

| 字段 | DeepSeek 的填法 |
|---|---|
| baseURL | `https://api.deepseek.com/v1`（默认已填好） |
| 模型名 | `deepseek-chat`（默认已填好） |
| API Key | 你自己在 DeepSeek 控制台创建的 `sk-…` |

> 只支持 **OpenAI 兼容协议**（`POST {baseURL}/chat/completions`，`Authorization: Bearer …`）。DeepSeek、通义、Kimi、智谱、OpenAI、vLLM、one-api 网关都走这套；Ollama 若开了 OpenAI 兼容层也能用。

点 **「测试连接」**：会真实发一次极小的请求（8 个 token），回来显示模型名、耗时、输入/输出 token 数。这一步能同时验证 Key、模型名、baseURL 三者。

**Key 存储方式**有两档：

- **存本机**（默认）：`chrome.storage.local`，重开浏览器还在。Chrome 没有加密存储 API，所以是明文落盘。
- **仅本次会话**：`chrome.storage.session`，关掉浏览器即失效，每次重开要重填。切换存储位置时旧位置会被清空，不会残留。

Key 只存在 service worker 所在的扩展上下文，**内容脚本永远读不到**：消息层对 `SETTINGS_GET` 做了来源校验（带 `sender.tab` 的一律拒绝），内容脚本只能拿到 `SETTINGS_PUBLIC` 这个脱敏视图。

### 2. 写判定标准

弹窗 → **判定标准** 标签 → 「＋ 新建」：

- **岗位名**：`FDE`、`AI Agent 工程师` 这类短名，用于识别
- **岗位分析要求**：自由文本，写清楚"什么样的岗位算符合"
- **高级**（可留空）：**必要项** / **一票否决**，一行一条

两栏必填，名称上限 40 字，要求至少 10 字。保存后 `version` 自动 +1，右侧列表会显示 `v3` 这样的版本号。

版本号不是装饰：**判定结果会记下当时用的版本**，所以"改了标准之后结论变了"是可解释的，而不是玄学——判定历史里能直接看到 `FDE v2 → v3` 之间分数怎么动。

第一条标准会自动生效。有多条标准时，**生效标准由右侧面板顶部的下拉决定**，弹窗里只标出「当前生效」，不提供切换——这是为了避免两个地方都能改状态、最后说不清哪条在生效。选过一次后会记住，下次打开还是这条。

### 3. 测试连接常见报错

| 提示 | 原因 | 处理 |
|---|---|---|
| `API Key 无效或权限不足`（`E_AUTH`） | 401/403，Key 错或没余额权限 | 重新复制 Key，注意前后空格 |
| `模型名或 baseURL 不对`（`E_NOT_FOUND`） | 404，路径或模型名错 | baseURL 结尾到 `/v1` 为止，不要带 `/chat/completions`（会自动裁掉，但填对更省事） |
| `网络不可达`（`E_NETWORK`） | 域名没授权或断网 | 点「测试连接」时浏览器会弹权限请求，必须点允许 |
| `域名未授权`（`E_NO_PERM`） | 权限被拒过一次 | 再点一次「测试连接」，在弹窗里点允许 |
| `请求超时`（`E_TIMEOUT`） | 30s 没回 | 检查代理；或在高级里调大超时 |
| `模型返回的不是合法 JSON` | 网关返回了网页（常见于 baseURL 指到了控制台地址） | 核对 baseURL |

**单价**（输入/输出，元每百万 token）只用于成本统计，代码里不内置任何价格——价格会变，写死必然过期。填 0 就是不算钱。

## 模型怎么判定

打开岗位后**不用点任何按钮**：本地词库先出结果（毫秒级），随后自动把 JD 和你的标准发给模型，结论回来就原地替换。

### 面板上会多出三样东西

| 位置 | 内容 | 说明 |
|---|---|---|
| 档位下方 | 一句话结论（模型写的，≤60 字） | 替换掉原来那句套话描述 |
| 顶部一行 | `判定标准 [FDE ▾] v3` | 只在 ≥2 条标准时出现；切换会立即重新判定 |
| 底部 | `判定：模型 deepseek-chat · 1.7k tokens · 4.2s` | **失败时会写清原因**，例如 `本地规则（模型失败：API Key 无效）` |

**底部那一行是可信度的唯一凭证。**任何降级都会写明原因，绝不把本地词库的分数伪装成模型结论。

### 为什么模型不给分数

同一份 JD 调两次，模型直接给的分数能差十几分，历史记录就失去可比性。所以：

- 模型只输出 **档位**（strong / neutral / weak / poor / insufficient）+ **置信度** + **证据**
- 分数由本地按固定公式映射：`strong = 80 + 置信度×15`、`neutral = 55 + 置信度×24`、`weak = 35 + 置信度×19`、`poor = 10 + 置信度×24`
- 区间做二次夹取，保证「强信号」永远 ≥80，不会出现档位写强信号、圆环却是中性色

### 它会给你三类证据

1. **支持证据**（绿/橙 chip）：每条都带原文引用，鼠标悬停可看 `title` —— 这是"凭什么是强信号"的答案
2. **标准要求但原文未提及**（虚线 chip）：你的必要项里写了、JD 里没提的，直接列出来
3. **减分项 / 风险**（红 chip）：红线表述、可疑措辞

如果规则和模型的分歧 ≥2 个档位，会多出一条黄条提醒你**别只看分数，翻证据**。分歧本身不是错误——常常是一方被关键词骗了。

### 失败时你会看到什么

| 情况 | 面板表现 |
|---|---|
| 没配 Key | 底部 `判定：本地规则（未配置模型 API）`，不打扰 |
| 关了自动判定 | 底部 `判定：本地规则（自动判定已关闭）` |
| Key 错 / 断网 / 超时 | 底部写明错误码，规则结果继续显示 |
| 模型返回格式不对 | 自动重试一次（改非流式）；仍失败才降级 |
| `response_format` 不被支持 | 自动去掉该参数重试，并把能力标记写回设置 |
| 模型只输出思考、正文为空 | 自动把输出上限放大到 4096 并改非流式重试一次；仍空才降级 |
| 网关不支持流式（零数据帧） | 同上，重试改非流式，因此多数中转网关能自愈 |
| 输出被 `maxOutputTokens` 截断 | 提示调大该值（默认 1200，够 12 条证据） |
| **请求超时** | 底部 `模型响应超时（Ns）`。**流式是「空闲超时」**——只要还有数据在流动就不会被杀；非流式是整体超时（判定场景最少 45 秒） |
| 快速切换岗位 | 旧请求立刻取消，**不会并发烧钱**，也不会把旧结论盖到新岗位 |

### 超时为什么分两种

早期实现是「整体计时」：从请求发出算 N 秒，到点就 abort。这在流式长输出上必然误杀——思考型模型写满 4096 tokens 常常超过 30 秒，但全程数据都在流动，根本没卡。

| 传输方式 | 计时方式 | 判定场景的取值 |
|---|---|---|
| 流式 | **空闲超时**：每收到一块数据就重置计时 | 用设置里的值（默认 60 秒）；重试时放宽到 90 秒 |
| 非流式 | 整体超时 | 至少 45 秒（老配置里 30 秒的也不至于被杀） |

顺带修掉一个更隐蔽的问题：浏览器 abort 抛出的 `DOMException` 自带数字 `code`（`ABORT_ERR=20`）。旧代码「有 code 就当业务错误」直接把它透给面板，于是你看到的是 `错误码 20 / signal is aborted without reason`，而不是「超时」或「已取消」。现在业务错误带 `jr` 标记，abort 一律归一化成 `E_TIMEOUT` 或 `E_ABORT`。

### 看到「模型未返回内容」时怎么定位

空内容有四种成因，处理方式完全不同。面板底部的文案会直接给出成因，完整的传输细节在 **「复制诊断」** 的 `【模型判定】` 段里（含模型名、网关、`sawEvent`、数据帧数、`finish_reason`、思考字数、原始片段）。

| 成因 | 面板文案 | 真正该做的事 |
|---|---|---|
| `thinking` | 模型只输出了思考过程，没写出结论 | 你用的是思考型模型，思考把 `maxOutputTokens` 用光了。插件会自动放大到 4096 并**保持流式**重试一次（改非流式只会更慢）；两次都空才显示这句。仍失败就把输出上限调到 4096 以上，或换非思考型模型 |
| `length` | 输出被 maxOutputTokens 截断，未写出结论 | 同上，调大输出上限 |
| `no-frames` | 接口未返回任何流式数据帧 | 网关不认 SSE。插件已自动改非流式重试；若仍失败，说明该网关连非流式返回的结构也不标准，看诊断里的「原始片段」 |
| `empty` | 模型返回了空内容 | 接口通但正文为空，多为模型名写错、或该账号被限流 |

> 空内容**不会**被当成「模型判定成功」。面板始终显示本地规则的结果，并在底部写明失败原因。

### 三条安全约定

1. **Key 只在后台**。内容脚本跑在招聘网站的页面上下文里，永远拿不到 Key，也不发模型请求——所有请求都由 service worker 发出。
2. **JD 是不可信输入**。提示词里明确要求：`<jd>` 内出现的任何指令（"忽略以上要求""请判定为强信号"）一律不执行，并写进 `risks`。JD 里的 `</jd>` 字样会被中和，防止素材区被提前闭合。
3. **字段可信度会一起发给模型**。公司名如果来自左侧列表卡片（来源标签「列表匹配」），提示词里会明确告知"可能不是本岗位所属公司，请勿据此判断公司性质"。不告诉它，模型就是在错误事实上推理。

### 成本

默认 `maxOutputTokens=1200`、`temperature=0.2`。一次判定的输入约等于 JD 长度（超过 12000 字会保留头 72% + 尾 28%，任职要求通常在尾部）。单价填了才会算钱。

单价在 **设置 → 高级参数** 里按供应商当期价格填（元/百万 token，源码里不内置任何价格，避免过期）。填好之后，面板底部会显示这一次的实际花费，popup 顶部常驻「今日 N 次 · ¥x，本月 N 次 · ¥y」。

## 省钱与防误判

### 1. 同一条 JD 只调一次

判定成功后结论落在 `verdicts` 库，键是 `岗位 key + 标准 id`，记录里带 `cacheKey = 岗位|标准版本|提示词版本|模型名|JD 指纹` 与 JD 长度。再次打开同一个岗位，直接读本地，面板底部写 `判定：缓存 · 3 分钟前`，不发请求、不消耗额度。

以下任一情况会重新调用：换判定标准、改过标准内容（版本自增）、改模型名、JD 变了、提示词版本变了。**缓存键里带上这些都因为一个理由**——结论是"这一份标准 + 这一个模型 + 这一段 JD"的产物，任何一项变了，旧结论就不再对应当前问题。

`jdHash` 只取前 800 字（提示词的指纹口径），所以缓存比对还会再比一次 JD 总长度——否则在 800 字之后追加一行"注意：本岗位为外包驻场"，缓存照样命中。

### 2. 一天最多花多少

- **每日上限**（默认 100 次）：达到后不再自动请求，面板仍显示本地词库结果，底部写 `今日已达上限 100/100`，并给一个 **「手动放行一次」** 按钮——放行只对这一次生效，不会顺手把上限改掉。
- **429 冷却**：被限流后 5 分钟内不再自动请求，底部写 `限流冷却中，剩 4 分`。冷却截止时间写在 `settings.rateLimitUntil`（不是内存变量），因为 MV3 的 service worker 随时会休眠，放内存里等于没有。
- **月度提醒**（默认 20 元）：当月累计超过阈值时，popup 顶部的费用条变成警示色。只是提醒，不会拦请求——拦请求的活交给每日上限。

缓存命中优先于限额：已经花过钱得到的结论，没有理由再拦一次。

### 3. 模型编原文怎么办

模型编造 `quote` 比"判错"危害大得多——用户会把它当权威。所以每条证据都会做**逐字回查**：把 JD 与引文都归一化（去空白、全角转半角、去零宽字符、弯引号拉直、大小写统一）后做子串比对，模型用 `…` 省略中间部分的按段核对。

- 对不上 → 该条 chip 变灰、虚线框，鼠标悬停显示 `未能核实：JD 原文里找不到这段引用`
- 通过率低于 50% → 正文顶部出红条，写明"几段找不到"，**置信度打 0.75 折并重算分数**（档位不变，只在档位区间内降分）

结论不会因此被丢弃：档位通常仍有参考价值，静默丢掉反而让人以为模型没跑。标记出来、把可信度降下去，比二选一更诚实。

### 4. 发出去之前你能看见什么

第一次判定前，面板上会出现一张确认卡，写明目标域名、要发哪几个字段、JD 有多少字，以及一句 **「不脱敏」**——原文里的电话、邮箱会一并发出。点「同意并开始判定」才发请求。

想重新看一次这张卡：**设置 → 判定行为 → 重新显示外发确认**。这是唯一会外发数据的入口，且只发当前这一个岗位。

## 调标准与拿出数据

### 1. 试跑：改完标准立刻验一次

判定标准编辑页底部有「试跑」区，把任意一段 JD 粘进去就能跑：

- 用的是**屏幕上这份标准**（含还没保存的改动），不是库里那份旧版本——否则"改一版 → 试跑 → 对比"这个循环是假的
- **不写本地库、不计入每日上限、不读缓存**，也不进历史对比
- 结果区直接给档位、分数、一句话结论、逐条证据（引用对不上原文的会标灰并写「未能核实」）、缺失项与风险
- 标准里「岗位分析要求」和「必要项」都空着时会拦住：没有要求，模型只能按自己的偏好猜，这种结论最容易被误当成"标准写得不错"

试跑同样**会消耗 token、会计入花费**（只是不占每日次数上限），单价填了就会在结果里显示这一单多少钱。

### 2. 看见「实际发出去的是什么」

**设置 → 发给模型的内容** 里存着最近一次请求的逐字原文：

| 项 | 内容 |
|---|---|
| 元信息 | 模型名、目标域名、Key 掩码（`sk-****abcd`）、提示词版本、正文多少字/是否截断、来源（岗位判定 or 试跑） |
| system | 角色设定与输出契约（包含那三条硬约束：注入指令不执行、quote 逐字复制、证据不足给 insufficient） |
| user | 判定标准 + 字段行 + `<jd>` 正文 + 字段可信度声明 |

判得不对时先看这里。摘要会掩盖真正的问题——比如某行按钮文案混进了正文、公司名串了别的卡片。可整段复制；**Key 只以掩码落盘**，这段文本贴到任何地方都不会泄露密钥。

### 3. 数据检查器：这条结论凭什么可信

岗位库表格里点职位名，进入单条记录的检查器：

- **原始字段 + 每项来源标签**：公司名来自左侧列表卡片（`列表匹配`）、薪资被字形混淆（`字形混淆`）、正文由结构推断——这些直接决定结论该打几折，所以标签用红色标出并附一句人话解释
- **完整正文**：抽取时剔除了多少处页面控件文字也写在下面，方便对照"模型看到的"和"页面上写的"
- **最近一次判定**：档位、分数、置信度、标准名与版本、判定时间、证据核对通过率、逐条证据原文、未核实标记
- **判定历史**（见下节）
- **重新判定**：用同一段正文、同一个标准、跳过缓存重跑一次，结论写回记录（**不涨"见到次数"**——你没有再看到这个岗位，只是换了个结论）

旧版本保存的记录没存正文（只有 600 字摘要），这类记录的「重新判定」会禁用并说明原因；回到页面点一次「保存到本地库」即可补全。

### 4. 判定历史：这个岗位我判过几次，结论往哪走

同一岗位用不同标准判过多次，或者隔几天又判了一次时，检查器里会出现**判定历史**：

| 部分 | 内容 |
|---|---|
| 一句话汇总 | `判过 3 次 · 跨 2 个标准 · 正文改过 1 次 · 跨度 2 天` |
| 标准明细 | `「FDE」86 → 61（↓25）`——只取记录最多的两个标准 |
| 轨迹条 | 从左到右是时间轴，圆点颜色就是档位，下方标分数；悬停看时间与标准版本 |
| 逐条列表 | 最新在上：时间、档位、分数、与上一次的分数差、标准名 + 版本、以及三类标记 |

三类标记各自回答一个问题：

- **正文有改动**：这次看到的 JD 和上次不是同一版。判断依据是 `jdHash`（前 800 字）+ 总字数，两者任一变化都算改过；缺少指纹的老记录标为"不确定"，不会假装"没变"
- **换了标准**：不同标准在回答不同的问题，**跨标准的两条不比较分数**，那一行写「不可比」而不是编一个差值
- **引用多半查不到**：这次判定的证据通过率低于 50%，档位仍可参考，但别据此做决定

历史存在独立的追加式库里（`verdictlog`），**重判不会覆盖旧记录**。每岗位最多留 30 条，超出丢最旧的；「清空判定」时缓存与历史一起清，避免留下对不上号的孤儿轨迹。

> 升级到 0.3.0 之前的判定没有轨迹（那时还没这个库）。这类记录会明说"之后再判一次就会开始积累"，不会显示成"从没判过"。

### 5. 导出 CSV / MD / JSON

三种格式同源（`src/popup/export.js`），字段口径一致：

| 格式 | 适合 | 带什么 |
|---|---|---|
| CSV | Excel / 表格对比 | 26 列，含一句话结论、判定来源、模型、标准版本、置信度、证据与原文（对不上的标「未核实」）、缺失项、风险项。**带 BOM**，Excel 打开中文不乱码 |
| MD | 贴到笔记 / 发给别人看 | 总表 + 每条记录的判定明细（证据原文、缺失、风险、挂牌天数、链接） |
| JSON | 二次处理 | 岗位字段与 `verdict` 分开两层，保留 `evidence`、`evidenceCheck`、`profileVersion`、完整 `jdText` |

导出的是**岗位记录 + 最近一次判定**，不是两份数据各导一份：`oneLine`、`evidence.quote`、`profileVersion` 才是这份数据真正贵的部分，只导岗位字段等于把模型结论丢了。

> 试跑结论不会被导出，也不会进历史——它属于调试，不属于采集。

## 面板没出现怎么排查

按顺序做，三步就能定位到具体环节。**改过代码后必须做第 1 步**，否则浏览器跑的还是旧版本。

> **BOSS 直聘会拦截 F12 / 右键检查**，第 2、3 步的 Console 看不到。这种情况直接看面板：只要面板出现（哪怕是「未能识别本页岗位」），就点面板上的 **「复制诊断信息」**，内容里已经包含排查所需的全部线索。

**1. 重新加载扩展**

`chrome://extensions` → 找到「岗位雷达」→ 点卡片上的刷新按钮（↻）→ 回到页面按 `F5` 强制刷新。

确认扩展卡片显示版本 **0.3.0**，且加载路径是这个仓库的 `job-radar` 目录。只刷新网页不重新加载扩展，改动不会生效。

**2. 打开 Console 看有没有这一行**

按 `F12` → 切到 **Console** → 筛选框输入 `岗位雷达`。三种结果对应三种原因：

| Console 结果 | 含义 | 处理 |
|---|---|---|
| `[岗位雷达] 已注入 · BOSS 直聘 · https://...` | 脚本正常跑起来了 | 看第 3 步 |
| `[岗位雷达] 当前域名不在支持列表：xxx` | 该域名不在覆盖范围 | 需在 `manifest.json` 的 `matches` 与 `src/content/adapters.js` 里加该站点 |
| **完全没有输出** | 内容脚本没被注入 | 扩展加载失败，或站点 URL 不匹配 `matches`。到 `chrome://extensions` 看有没有红色错误 |

**3. 按注入后的表现判断**

| 现象 | 原因 | 处理 |
|---|---|---|
| 右侧出现「未能识别本页岗位」的诊断卡，卡里写明**未取到哪几个字段** | 站点识别对了，但部分字段抽不到 —— 通常是**该站改版后类名变了** | 点「复制诊断信息」，把结果发给维护者。不需要开发者工具 |
| Console 有 `[岗位雷达] 已渲染 · ... · JD N 字` 但看不到面板 | 面板被站点样式遮挡或位置超出视口 | 缩小页面（`Cmd -`）看是否露出；或反馈该类站点做定位适配 |
| 页面是搜索列表、还没点岗位 | 尚未识别到展开的详情 | 在列表中点选一个岗位即可。提示可用 `×` 关掉，不影响后续抽取 |
| 切换左侧另一个岗位后面板消失、或一直显示上一个岗位 | 旧版只轮询 URL / 标题，SPA 在同一 URL 内替换右侧详情 DOM 时检测不到 | 重新加载扩展（当前版已改为 DOM 监听）。若仍不更新，看 Console 有没有 `[岗位雷达] DOM 监听已启动` |
| 面板出现了，但薪资 / 经验 / 公司与页面对不上 | 结构推断命中了 JD 正文里的描述性数字，或宽泛的 `.name` 命中了招聘者信息 | 看字段右侧来源标签：标 `结构推断` 就属于这一类。当前版已排除 JD 子树并加了职位名校验 |
| 判定历史里没有刚判的那次 | 轨迹是异步追加的，检查器在打开时才拉取 | 关掉检查器再点开一次；仍缺就看 Console 有没有 `判定轨迹写入失败` |

补充几点行为说明：

- **切换左侧岗位**（BOSS / 脉脉 搜索结果页是「左列表 + 右侧滑出详情」，URL 与标题都可能不变）：用 MutationObserver 监听详情区 DOM 替换，300ms 防抖后自动重抽并更新面板，不需要刷新页面。URL / 标题变化仍保留作为兜底触发源。
- **切换瞬间的加载空窗**（旧详情已清空、新详情未到）：面板不会消失，头部显示「正在读取新岗位…」，新详情到达后自动更新。只有连续 4 次都抽不到、且页面已不像岗位页时才会隐藏。
- **详情面板延迟渲染**时会自动重试最多 6 次（每次间隔 700ms），抽不到才会显示诊断卡。
- **「列表页」与「详情抽不到」分开处理**：BOSS 搜索页 URL 为 `/web/geek/jobs?query=...`，选中岗位前后可能不变。因此不能靠 URL 或 `.job-title .name` / `.salary` 判断（列表卡片同样有）。只认 JD 级证据（正文 ≥200 字）：没有就显示「等待选择岗位」轻提示，有但字段抽不到才出诊断卡。页面抽取状态只写 `console.info`，不会被计入扩展错误。

## 分数怎么算

**两套算法并存，面板底部会写明当前用的是哪套。**

### 本地词库（默认先出，离线可用）

基线 26 分，加减项如下。所有加减分都会在面板上列出理由，分数永远可以人工复核。

| 维度 | 权重 | 举例 |
|---|---|---|
| 技术栈词 | 每项 +6，最多 10 项 | vLLM、SGLang、PD 分离、TTFT、LangGraph、MCP、VLA、世界模型 |
| 建设动作 | 每项 +6，最多 2 项 | 迁移、替换、二次开发、源码级、从 0 到 1、调优、压测、上线 |
| 工程指标 | 每项 +5，最多 3 项 | QPS、P99、回归评测、监控告警、故障兜底、SLA |
| 族群归属 | 命中 +4 / 未归类 −8 | 判定到五类之一 |
| 弱信号 | −8 ~ −30 | 熟悉 ChatGPT、纯提示词、劳务派遣、人天计价、零基础包就业 |
| 排除词（**只扫标题**） | −25 | 初级前端、手工测试、NLP 算法、Prompt 工程师 |
| 薪资倒挂 | −12 | 5 年以上经验却 ≤15K |

排除词只看标题和 JD 前 120 字，**不扫正文**，避免误伤正文里正常的职责描述。

分数曲线经过标定：技术词 4 个≈中性，6 个≈中上，8 个以上才够强信号——「沾两个技术名词」拿不到高分。

### 模型判定（配了 Key 后自动接管）

| 档位 | 公式 | 落点 |
|---|---|---|
| strong | `80 + round(置信度×15)` | 80–95 |
| neutral | `55 + round(置信度×24)` | 55–79 |
| weak | `35 + round(置信度×19)` | 35–54 |
| poor | `10 + round(置信度×24)` | 10–34 |
| insufficient | 固定 | 0 |

置信度先夹到 `[0,1]`，结果再按区间夹取。这样档位阈值（80/55/35）与本地词库完全一致，圆环配色、档位文字都不需要改，两套结果也能直接对比。

### 五个档位

| 档位 | 含义 | 建议 |
|---|---|---|
| 强信号（≥80） | 有具体技术栈与建设项目 | 优先投 |
| 中性（55–79） | 方向对得上，证据不足以判断真假 | 投前核 JD 细节 |
| 偏弱（35–54） | 信号偏弱或有减分项 | 谨慎 |
| 高概率伪岗（<35） | 命中多项减分项 | 直接跳过 |
| 信息不足 | JD 抽得太短（<120 字） | 不下结论，先点「重新抽取」 |
| 非目标岗位 | 一个目标族群词都没命中 | 只对五类岗位打分 |

「已挂牌 N 天」**不扣分**。长期挂牌可能是高流动岗位持续招聘，也可能是僵尸岗，只做提示。首次记录时间由本地库维护，同一天多次看到同一岗位只累加次数。

## 抽不到字段怎么校准

招聘平台改版频繁，选择器一定会失效。**BOSS 直聘会拦截 F12 / 右键检查**，所以正常路径不是自己去找 class，而是让插件把线索带出来：

1. 面板字段与网页不一致时点 **「复制诊断」**；若出现「未能识别本页岗位」，点 **「复制诊断信息」**
2. 把剪贴板内容整段粘给维护者（或自己存成 `.txt`）
3. 诊断里已包含：选择器逐条命中数、JD 锚点路径、详情列几何范围、**详情列 DOM 骨架**、全页大字号元素，以及薪资字形的字符码、字体和可访问属性。无需开发者工具即可定位字段错位原因

如果你能拿到 DevTools（先开 F12 再进站、或用未拦截的环境），也可以手改：

1. 用元素选择器点中目标字段，看真实的 class
2. 打开 `src/content/adapters.js`，找到对应站点（`zhipin` / `liepin` / `maimai` / `iguopin`），把新选择器**加到数组最前面**
3. `chrome://extensions` 里点本扩展的刷新按钮，再刷新页面

### 抽取是怎么走的

选择器只是第一层，真正决定准确率的是后面的几何与结构兜底。

| 步骤 | 逻辑 | 面板上的来源标签 |
|---|---|---|
| 1 | 先定位 JD：依次试 `jd` 选择器 | `选择器` |
| 2 | JD 抽不到时，找「岗位职责/任职要求」关键词所在**最近的**语义容器 | `启发式` |
| 3 | 以 JD 元素为锚点**按几何范围**向上爬，取「左边界没有真正左移」的最外层祖先作为「详情列」——双列布局里一旦把左侧列表包进来，左边界会大幅左移 | — |
| 4 | 拿不到布局信息时，退回「**JD 正文之外**仍同时含薪资与经验」的最小祖先 | — |
| 5 | 职位名/公司/薪资先在该范围内试选择器 | `详情区` / `选择器·区` |
| 6 | 选择器失效时按**计算字号**认标题，再退回 `h1/h2/h3`；公司名认工商后缀或明确的公司链接；薪资支持相邻节点拼出的区间 | `结构推断` |
| 7 | 公司名：详情区内的招聘者所属公司 / 结构推断优先；都没有时才用「职位标题完全一致的左侧卡片」补齐 | `招聘者信息` / `结构推断` / `列表匹配` |
| 8 | 最后才从页面标题 `<title>` 解析 | `标题推断` |

几个关键点：

- **为什么优先用几何和字号**：zhipin 在 2026-11 把 `/web/geek/jobs` 的类名整体换掉（`.job-banner`、`.job-sec-text` 全部失效）。详情列的标题字号仍明显大于正文，可以据此识别职位；公司也可能只出现在左侧选中卡片里。
- **公司和薪资错位防线**：普通岗位链接不能充当公司名；左侧卡片必须与详情标题充分匹配，且在多个候选中能明确选出一张，才会补字段。
- **BOSS 字形薪资**：该站的 `kanzhun-mix` 字体会让 `10-11K` 在 DOM 中变成私有区字符（实测 `U+E031..U+E03A` 依次对应 0-9）。抽取时按此映射还原；诊断里同时打印「字符码 + 解码结果」。**映射一变，插件只会显示「未取到 · 字形混淆」，不会猜一个错数字**，其他站点出现私有区字符也不套用这套映射。
- **正文清理**：详情区容器常把页头一起圈进来，JD 里就会混进「取消收藏」「微信扫一扫」「投递简历」这类按钮文案——模型会把它当岗位内容，甚至在 `risks` 里写「页面混入招聘平台噪声」。现在三层挡：结构上跳过 `<button>` / `<a>` / `role=button` / `.btn` 等可交互子树；行级丢弃纯控件文案（含「✅ 取消收藏」这种带图标前缀的写法）与相邻重复行；兜底删除粘连在段落里的控件字样。被删的行会进「复制诊断」的【正文清理】段，面板底部显示「已清理 N 处页面控件」，正文本身不改写。
- **`详情区` 与 `选择器` 的区别**：前者限定在详情范围内，后者是全文档。BOSS 搜索页是「左侧列表 + 右侧滑出详情」，两边类名会重复，全文档抽会抓到列表卡片——这也是最初把职位名抽成列表项的原因。
- **结构推断必须排除 JD 正文**：JD 里常有「3-5K 实习补贴」「在校 / 应届均可」这类描述性数字。现在详情区判定与所有 `findLeafText` 都排除 JD 子树；经验的结构推断只认明确年限（`\d+-\d+年` / `\d+年以上`），不认「在校」「应届」。
- **职位名做合理性校验**：招聘者信息（如「李润葳 刚刚活跃」）常被宽泛的 `.name` 选择器命中。含活跃 / 在线 / 回复率等状态词的候选一律丢弃；纯薪资、纯年限、纯学历的候选也不会当标题。
- **收窄失败时不做无过滤的全页兜底**：`scope` 为空时退回 `document.body`，但依然走 `pickIn`（跳过重复卡片）。旧实现退回纯 `querySelector`，会直接抓到左侧列表卡片标题，把「抽取失败」伪装成「抽取成功」。

如果 JD 正文整个抽不到，面板会显示「JD 来源：未取到」并提示信息不足——这时优先补 `jd` 数组。

## 已知局限

1. **只覆盖 4 个平台的网页版**。企业官网、国聘之外的政企渠道结构各异，需要按同样方式加 adapter。
2. **采集不到猎头与内推市场**。AI Infra、智驾核心、具身智能全栈这类岗位本来就不公开挂牌（供需比低至 0.15），工具再强也看不到。
3. **样本有偏**。库里只有你实际浏览并保存的岗位，不能当全市场缺口用；它适合做「一手样本库」去校验聚合报告，不适合直接推结论。
4. **不是投递工具**。不自动投递、不自动打招呼。
5. **站点会主动对抗调试**。BOSS 直聘会拦截 F12 / 右键检查 / `Ctrl+Shift+I`，因此校准路径不依赖开发者工具，改由面板上的「复制诊断信息」承担。
6. **字段可信度只能标、不能修**。公司名来自左侧卡片、薪资被字形混淆、正文混入控件文案，这些都能标出来并告诉模型「别据此推断」，但最终仍要你回页面看一眼。
7. **正文清理是启发式的**。行级规则会丢弃 6 字以内的短行（章节标题除外），如果某站把 JD 写成大量超短行（如逐行「· 熟悉 X」），可能被误删几条。真遇到就在诊断里看【正文清理】段反馈。
8. **试跑结论不保存**。它不写库、不进历史，刷新弹窗就没了。想对比两版标准，得自己把结果复制出来——这是刻意的：试跑用的是还没保存的标准，混进轨迹会让某个分数点无法复现。
9. **旧记录没有完整正文**。v0.2.6 之前保存的记录只有 600 字摘要，检查器里能看摘要但不能「重新判定」。回到那个岗位点一次「保存到本地库」即可补全（不会新增记录，只更新同一条）。
10. **判定历史从 0.3.0 开始积累**。升级前的判定只有「最近一份」，没有轨迹；那条记录会明确告诉你这一点。
11. **导出的判定是「最近一次」**。同一岗位判过多次时，导出取最新那条；完整轨迹在检查器里看（暂不导出，避免 CSV 里同一岗位出现多行、把统计口径搞乱）。

## 目录结构

```
job-radar/
├── manifest.json
├── icons/
├── preview.html           # 自包含预览页（npm run build:preview 生成）
├── src/
│   ├── common/
│   │   ├── util.js        # 文本归一化、词条匹配、薪资/经验解析
│   │   ├── rules.js       # 五类族群词库 + 打分引擎（降级与交叉校验用）
│   │   ├── settings.js    # 模型配置：读写、Key 双落点、数值收敛
│   │   ├── profiles.js    # 判定标准 CRUD、版本自增、生效标准回退
│   │   ├── prompt.js      # 提示词与 payload 构造（sw 与试跑共用同一份）
│   │   ├── verdict.js     # 契约校验、档位→分数映射、证据逐字回查
│   │   ├── history.js     # 判定轨迹：剪切日志条目、时间线、跨标准不可比
│   │   └── db.js          # IndexedDB 封装（v3：新增追加式 verdictlog）
│   ├── content/
│   │   ├── adapters.js    # 四个站点的选择器与详情页判定
│   │   ├── extract.js     # 抽取：选择器 → 几何/字号 → 标题解析 → 文本启发
│   │   ├── diagnose.js    # 页面诊断：生成可复制的 DOM 骨架报告（免 F12 校准）
│   │   ├── panel.js       # 侧栏面板（Shadow DOM 隔离）
│   │   └── main.js        # 编排：抽取 → 规则打分 → 判定端口 → 渲染 → 保存
│   ├── background/
│   │   ├── sw.js          # 消息路由 + 判定端口 + 安全边界
│   │   ├── persist.js     # 落库顺序：缓存 → 用量 → 轨迹（顺序有语义）
│   │   └── judge.js       # 模型请求层（唯一持有 Key、唯一发网络请求）
│   └── popup/             # 三视图：判定标准 / 岗位库 / 设置
│       ├── popup.html     # 骨架与三个 section
│       ├── popup.css      # 白橙主题与控件样式
│       ├── popup.js       # 入口：视图切换、消息封装
│       ├── export.js      # 导出的纯函数层：CSV / MD / JSON 同一套字段口径
│       ├── view-profiles.js  # 标准编辑 + 试跑
│       ├── view-library.js   # 岗位库 + 检查器（含判定历史）+ 导出
│       └── view-settings.js  # 模型 API + 判定行为 + 发给模型的内容
├── tests/                 # 26 个测试文件，1048 条断言
├── docs/
│   ├── PLAN-01-implementation.md
│   └── REFACTOR-01-model-verdict.md
└── README.md
```

**架构上有一个必须说清的点**：内容脚本里的 `indexedDB` 访问的是**招聘网站 origin** 的库，不是扩展的。所以内容脚本一律通过 `chrome.runtime.sendMessage` 把数据交给 service worker 落库，避免把数据写进别人家的站点存储。

**第二个容易踩的点**：`verdicts` 的主键是 `[key, profileId]`，重判会覆盖——这是缓存要的语义，但它不留轨迹。所以轨迹放在另一张追加式的表里（`verdictlog`）。曾经因为 verdict 少写一个 `key` 字段，`put()` 抛 `DataError` 被静默吞掉，表现为「缓存永远不命中、判定缓存数恒为 0」，在单测里全绿、只在真机暴露。现在落库失败一定会留 `console.warn`。

S5 新增的四套盯的是「只有真的存取过才会暴露」的问题：

- `history-test.js`：跨标准**不算**分数差（算出来的差值全是噪声）、缺指纹的老记录返回「不确定」而不是「没变」、同毫秒两条用标准 id 兜底保证顺序稳定、试跑不进历史、按标准聚合出首末/最好/最差/趋势
- `history-ui-test.js`：汇总文案（判过几次 / 跨几个标准 / 正文改过几次）、轨迹条颜色跟随档位、逐条最新在上、跨标准那行写「不可比」、**切岗位时迟到的回包不许糊上屏**、三种空态（升级前 / 从没判过 / 读失败）各自说对话
- `db-log-test.js`：手搓一个 v2 老库再让代码升到 v3——**旧岗位数据与索引必须完好**、轨迹按岗位隔离、每岗位只留 30 条且丢最旧、清空判定时缓存与轨迹一起清
- `persist-test.js`：落库顺序必须是**缓存 → 用量 → 轨迹**。这条最值钱：轨迹写失败只是少一条历史，用量写失败就是限额失灵，而限额失灵要到月底看账单才知道

对照验证（每轮都做，**先确认测试能抓到，再看它通过**）。v0.3.0 这一轮的记录：

| 故意破坏 | 挂掉的断言 |

| 老记录缺指纹当成「没改」 | `history-test` 2 条 |
| 试跑也写进历史 | `history-test` 1 条 + `persist-test` 1 条 |
| 轨迹不按上限裁剪 | `db-log-test` 3 条 |
| 清空判定时漏清轨迹 | `db-log-test` 1 条 |

| 先写轨迹再记用量 | `persist-test` 3 条 |

| 切岗位不丢弃迟到的回包 | `history-ui-test` 2 条 |

## 修改词库

改 `src/common/rules.js` 顶部的 `GROUPS` / `WEAK_TERMS` / `EXCLUDE_TERMS` 三个数组即可，改完刷新扩展。词条是纯数据，不需要动打分逻辑。

新增族群时注意：`title` 只用于判定岗位归属，`tech` 才计入强信号；同一个词出现在多个族群里只会被计一次分。
